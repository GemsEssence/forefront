# The audit log is Forefront's own table, written from operations

Audit events are rows in a Forefront-owned table, written explicitly by the classes in `app/operations/` (which every write already goes through), rather than being captured by model callbacks from a gem such as `paper_trail` or `audited`. Forefront is mounted inside other people's apps, so adding a versioning gem imposes that dependency, and possibly a conflicting version of it, on every host. Callback-based versioning also cannot record events that aren't row changes, such as a Staff member revealing a Customer's contact details or the Signup API being called, and those are the events this log exists to show. The cost is that a write made outside an operation isn't audited, so new writes must go through operations.
